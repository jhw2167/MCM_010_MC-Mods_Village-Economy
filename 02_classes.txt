CONFIG LAYER (implemented)
---
com.holybuckets.villageecon.config

VillageEconConfig            @Config(toml), plain Balm reflection paradigm (no ConfigNumber).
                             devMode, villageEconomyConfig path, villageStructures registry list
                             (@NestedType(String.class) - structures treated as villages, e.g.
                             "minecraft:village_plains"), DefaultEconomyConfigs (growthFactor,
                             demandDampeningFactor, globalInterestRate, start levels,
                             assignedLuxuryResourceCount, cycleLengthDays, markup), plain DEF_*
                             constants. Registered in CommonClass.

ModConfig                    (011) Singleton loader. init(EventRegistrar) hooks onBeforeServerStarted
                             (High) / onServerStopped (Low). Loads JSON via HBUtil.FileIO.loadJsonConfigs
                             with buildDefaultConfig() fallback, hydrates items/tags, prunes invalid
                             resources, resolves villageStructures -> Set<ResourceLocation>.
                             Accessors: getResource(id), getResources(type), isVillageStructure(loc),
                             getPersonalitiesForBiome, getLuxuriesForBiome, static getDefaults().

VillageEconomyJsonConfig     (010) IStringSerializable root JSON model. Scalars + ordered maps of
                             staples/basics/luxuries, personalityModifiers, cycleModifiers.
                             Guarantees a 'none' cycle modifier exists.

config.model.EconomyResource     (007) type STAPLE|BASIC|LUXURY, item + optional useTags (#tag),
                                 production[]/consumption[] level-indexed (Rho), weight, biome lists.
                                 hydrate() resolves Item/TagKey at server start; matches(ItemStack).
config.model.VillagePersonality  (008) THE shared modifier class: markup, interestModifier,
                                 demand/production modifier maps (default 1), biome lists. Used for
                                 both the personalityModifier and biomeModifier village state.
config.model.CycleModifier       (009) id, displayName, weight, demand/production modifiers.
                                 One drawn per village per cycle; ADDITIVE with other modifiers.


CORE LAYER (scaffolded)
---
com.holybuckets.villageecon.core

VillageManager          (012) Singleton initialized with the OVERWORLD ServerLevel on level load.
    - Map<ChunkPos, VillageEconomy> villages; addVillage(); getVillageCount() -> V.
    - Maintains the overall cycle sequence: dayOfCycle + cycleIndex, persisted via
      DataStore WorldSaveData on DatastoreSaveEvent.
    - handleStructureLoaded(StructureLoadedEvent): if structure is in villageStructures
      and firstTimeLoaded -> new VillageEconomy + createMayor(); reloads resolve via NBT.
    - 3 tick-based cyclic processes, propagated down:
        tickProcess()  ON_120_TICKS  -> each village -> Mayor.tickProcess()
        dailyProcess() onDailyTick(OVERWORLD_LOC) -> production+interest; advances cycle clock
        cycleProcess() every cycleLengthDays -> village cycleProcess + TradeEngine.executeScheduledTrades()

core.model.VillageEconomy  (013) implements IMangedChunkData (ManagedChunk pattern).
    - Created on StructureLoadedEvent for configured village structures.
    - Holds only IMMUTABLE data that survives mayor death: mayorId UUID, villageLevel,
      personalityModifier + biomeModifier (both VillagePersonality instances, persisted
      to the chunk as state ids), assigned luxuryResourceIds.
    - createMayor(): spawns Mayor Villager at origin, passes level + both modifiers.
    - getActiveResources(): staples; +basics at basicResourceStartLevel;
      +assigned luxuries at luxuryResourceStartLevel.
    - registerManagedChunkData() called in VillageManager.init; resolveSubData registers
      with VillageManager; serializeNBT/deserializeNBT persists state ids + mayorData.

core.model.Mayor        (015) Wraps the Mayor Villager entity (UUID). Holds most DYNAMIC data:
    - staticLedger: true current resources owned by the village
    - theoLedger: theoretical values after speculative trades; rectified each 16 day cycle
    - currentCycleModifier, demand map, working villageLevel.
    - tickProcess(): recalculateDemand() -> d = (1 - z*q) * b * D  (+ r/q TODO), then
      speculativeTrades() with tryBuy()/trySell() stubs against theoLedger.
    - dailyProcess(): production * productionModifier + daily interest -> staticLedger.
    - cycleProcess(): theoLedger.diff(staticLedger) -> surpluses = incoming trades,
      deficits = outgoing trades (TradeEngine.schedule*); floored quota rewards; level up
      when all quotas met; theoLedger rectified; new cycle modifier drawn by weight.
    - favoribility(j)/productionModifier(j): personality + biome + cycle - 2, clamped.

core.model.ResourceLedger (014) resource id -> item count, + currency.
    - add/remove/get, copyOf, diff(other) for reconciliation, NBT serialization.

TRADE LAYER (scaffolded)
---
com.holybuckets.villageecon.core.trade

Bazaar          (019) Singleton per level (Overworld only for now), Map<LevelAccessor, Bazaar>.
    - Map<Item, Market> markets; addMarket(Item); postBuyOffer/postSellOffer(Item, Post);
      static buyOffer/sellOffer(Level, Item, Post).
    - Global sale log (List<Sale>, transient); recordSale(Sale) -> log + market rate update.
    - Created on overworld level load; adds a Market per configured resource and seeds
      each MarketRate with the initial rate r/q added N times (phases out with real trades).

Market          (020) One resource's open market. Queue<Post> buys, List<Post> sells.
    - buy(Post) / sell(Post).
    - flushMarket(): per buyer, filter sellers within buyer's chunk radius
      (VillageEconomy::getBuyRadius = villageLevel * buyRadiusPerLevelChunks toml),
      random eligible seller, haggle. Each buyer/seller trades once per tickTrade;
      posts removed after their attempt.
    - haggle(buy, sell): weight_i = |d_i|/(|d_i|+|d_k|);
      price = reserveSell + weight_i*(reserveBuy - reserveSell).
      No zone of agreement (reserveBuy < reserveSell) -> natural fail; plus a
      tradeFallthroughChance random fail. qty = min(quantityDemands).
      Updates both ledgers via ResourceLedger::logTrade, then Bazaar::recordSale.

Post            (021) village, demand (d), quantityDemand, demandReserve, ledger.
                One offer per resource per village per tickTrade; buy XOR sell.
Sale            (022) seller, buyer, salePrice, saleQuantity, saleTime, resource Item
                (+resourceId for ledger keys). Immutable.
MarketRate      (023) Volume-weighted moving average of last N trades
                (N = marketRateTradeWindow toml). seed(rate) adds the seed N times.

Trade flow per tickTrade (120 ticks): VillageManager sorts villages by wealth (desc) ->
each Mayor recalculates demand, rolls agreeableness ~N(personality.agreeableness,
agreeablenessStdDev) clamped [0,1], picks buy XOR sell per resource (more profitable
side vs market rate), derives demandReserve (buy: a*d; sell: d*(2-a)) and posts to the
Bazaar -> Bazaar.flushMarkets() haggles everything against theoLedgers.

toml (TradeConfigs): marketRateTradeWindow, tradeFallthroughChance, agreeablenessStdDev,
buyRadiusPerLevelChunks. JSON: personality 'agreeableness' (0..1, default 0.5).

ORDERING / LIFECYCLE
---
CommonClass.init -> registerConfig(VillageEconConfig)
VillageEconomyMain.init -> ModConfig.init(registrar) [JSON load, priority High]
                        -> VillageManager.init(registrar) [+ VillageEconomy.registerManagedChunkData]
onLevelLoad(OVERWORLD) -> VillageManager INSTANCE created with overworld + cycle state loaded
onServerStopped -> singletons reset (INSTANCE = null).
